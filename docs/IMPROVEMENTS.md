# PLCFuzz 改进建议

本清单按对研究结论可靠性和持续维护的影响排序。它描述的是后续工作，不表示当前实现已经完成这些能力。

## P0：先保证结论可信

### 明确定义竞争问题判定 oracle

当前 `BufferHistory::checkChange()` 把观测窗口内的输出变化作为异常信号。这可以用于筛选可疑输入，但输出变化本身不等于并发数据竞争。应明确威胁模型，区分确定性逻辑切换、调度相关不一致和真正的共享状态竞争，并建立带真值标签的正反例。报告结果时应使用“候选问题”而不是直接宣称数据竞争。

### 固定 fuzz 输入协议

运行时、grammar、种子解析器和自定义变异器依赖同一套固定顺序文本格式，但目前没有版本字段或单一 schema。建议定义格式规范与版本号，由一处实现负责解析/序列化，并增加畸形输入、边界值、截断输入和向后兼容测试。

### 给历史语料建立清单

新版 MatIEC 扫描中有 23 个历史 ST 文件通过、13 个失败；失败文件已经原样移至 `testcases/archive/incompatible-matiec/`。下一步应把当前 Markdown 清单升级为机器可读 manifest，至少记录原路径、预期 profile、预期成功/失败、来源、许可和对应研究用途。

## P1：提升自动化和故障分析能力

### 替换脆弱的变量映射提取

`static_analyse/main.py` 当前用正则解析生成的 `src/glueVars.cpp`。生成器排版或类型转换形式改变就可能漏报。优先从 OpenPLC 的 `VARIABLES.csv`、MatIEC 符号信息或 glue generator 的结构化输出生成映射，并用集成测试核对变量数量、类型和地址。

### 建立 CI

Linux CI 至少应执行：submodule 初始化、MatIEC 构建和 `make check`、新增合法用例验证、PLCFuzz 单元测试、普通目标构建、自定义变异器构建以及 AFL++ 插桩目标构建。缓存只能加速依赖，不应绕过固定 commit 检查。

### 增加 sanitizer 与崩溃分流

为普通目标和自定义变异器增加 ASan/UBSan 配置。对 AFL++ 发现自动执行去重、最小化、稳定复现和堆栈采集，并将编译器 commit、目标 hash、seed、环境和命令写入每次实验的元数据。

### 让变异完全可复现

`MutatorState` 保存了 AFL++ 提供的 seed，但部分策略仍调用进程级 `random()`。应统一使用状态内的 PRNG，并针对固定 seed 验证输出完全一致。

### 强化 CSV 和配置错误处理

变量映射读取目前依赖简单逗号切分和 `std::stoi`，错误文件可能触发异常或生成部分全局状态。应使用显式校验、行号诊断和失败返回值，并把映射表收进 `MutatorState`，避免进程级可变全局数据。

### 自动记录实验目录

每次 fuzz run 应使用独立目录并生成 manifest，包括 Git commit、MatIEC commit、目标 hash、AFL++ 版本、机器信息、超时、持续时间和环境变量。这样能避免覆盖历史 `findings/`，也便于跨版本比较。

## P2：改善发布与长期维护

- 为原创文件补充版权和 SPDX 标识，并添加第三方组件所需的完整 `LICENSES/` 文本。
- 核对第三方测试用例的来源与再分发权。
- 将 `buildscript_new.sh` 等历史入口逐步迁移为语义明确的 `scripts/` 命令，并保留带弃用提示的兼容包装器。
- 继续用 RAII、明确所有权和强类型地址替代裸指针、整数索引与全局状态；特别检查 history buffer 的空指针和越界行为。
- 为 README 中的 Linux 全流程提供一次可重复的容器验收，并保存最终镜像 digest。
