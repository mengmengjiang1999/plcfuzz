## Context

The top-level Makefile discovers C++ files with a wildcard. Four files in `src/` are entirely commented and `interactive_server.cpp` contains only global definitions plus disabled historical code, yet all are compiled into every target. Backup files beside the active custom mutator and grammar have no ownership marker. `src/glueVars.cpp` and the root CSV are generated but intentionally tracked so a checkout can be inspected and partially compiled without regenerating a PLC program.

## Goals / Non-Goals

**Goals:**

- Make membership in the runtime build deliberate and reviewable.
- Keep historical implementation material without presenting it as active source.
- Establish one active grammar, mutator, and variable-mapping path.
- Document and verify the tracked generated reference snapshot.

**Non-Goals:**

- Re-enabling the disabled network services.
- Changing the generated glue format or variable extraction algorithm.
- Removing immutable experiment outputs from `artifacts/legacy/`.

## Decisions

1. List maintained runtime `.cpp` files explicitly in the Makefile and append `src/glueVars.cpp` as the generated source. New modules must be deliberately added.
2. Create `src/runtime_globals.cpp` containing the few globals still required by `main`, DNP3, and persistent storage. Move the disabled interactive server and fully commented protocol files to `artifacts/legacy/openplc-disabled-source/`.
3. Keep one old tagged-block grammar and the pre-refactor mutator under `artifacts/legacy/fuzz-config/`, with a README explaining that they are reference material. Remove the byte-identical second grammar copy.
4. Remove `static_analyse/plc_variables_mapping.csv`; the analyzer already writes to the root CSV by default. Keep the root CSV and `src/glueVars.cpp` as a matched, tracked reference snapshot regenerated by `buildscript.sh ... analyze`.
5. Add a structural validation script that checks the explicit source list, active/archival separation, absence of duplicate mapping copies, and root mapping agreement with the tracked glue snapshot.

## Risks / Trade-offs

- **A needed source can be omitted from the explicit list** → Compile all maintained translation units strictly and validate the list against the expected manifest.
- **Moving historical files can break old ad hoc paths** → Document new archival paths; Git history preserves the former paths.
- **Tracked generated files can become stale** → Validate that running the analyzer on the tracked glue produces the same root CSV.

## Migration Plan

Current builds continue through the Makefile and root scripts. Anyone referencing backup filenames directly must use the corresponding path under `artifacts/legacy/`.
