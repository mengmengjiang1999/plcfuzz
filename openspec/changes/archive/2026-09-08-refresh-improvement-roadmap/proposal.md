## Why

The improvement roadmap still presents three completed reliability changes as pending work, so it no longer matches the repository's implemented and verified state. Refreshing it now provides an accurate baseline before the remaining themes are handled one at a time.

## What Changes

- Separate completed improvements from pending work in `docs/IMPROVEMENTS.md`.
- Link completed entries to their archived OpenSpec changes and verification scope.
- Keep the eleven remaining themes ordered by research reliability and maintainability impact.
- Use neutral academic software-quality terminology throughout the roadmap.

## Capabilities

### New Capabilities

- `improvement-roadmap`: Defines how completed and pending project-improvement themes are represented and kept traceable to OpenSpec history.

### Modified Capabilities

None.

## Impact

This change affects only the maintained improvement roadmap and its OpenSpec records. Runtime behavior, test inputs, and retained experiment data are unchanged.
